# 묶음 1 실화면 확인 순서 — 협력사 구조

작성 2026-10-06 · 대상: 묶음 1 코드 배포 후 · 선행: mig 211a, 211c, 212, 213, 214 실행 완료

확인은 **A → B → C → D → E** 순서로 합니다. A 는 직원 등록 전에, B 부터는 등록 SQL 실행 후에 합니다.
각 단계에서 "기대"와 다르면 그 자리에서 멈추고 화면 문구를 그대로 알려 주세요.

## A. 운영자 — 직원 등록 전 (기존 동작이 그대로인지)

배포 후 앱을 닫았다 다시 엽니다. (211c 때 이미 재로그인했다면 다시 로그인할 필요는 없습니다.)

| # | 할 일 | 기대 |
|---|---|---|
| A1 | 홈·작업 목록 열기 | 평소와 같음. 작업 수·기사 이름 표기 변화 없음 |
| A2 | 직영 작업 1건 → 배정 추천 화면 | 추천 기사 목록이 평소와 같음 |
| A3 | 직영 기사 1명 배정 → 다른 기사로 재배정 | 정상 저장, 기사 폰에 배정 알림 |
| A4 | 냉매 접수 1건 자동 배정 화면 진입 | 후보 기사들에게 수락 요청 알림이 평소대로 감 |
| A5 | PC 대시보드 "오늘 원청별" 표 / 통계 허브 | 숫자가 배포 전과 같음. 협력사 행은 아직 없음(협력사 작업 0건) |
| A6 | 설정 → **협력사 관리** (PC 는 왼쪽 메뉴 기사 → 협력사) | 화이트코어 1건, 관리자 0명·직원 0명 |
| A7 | 협력사 관리 → 화이트코어 수정 → 메모에 아무 글자 입력 후 저장 | 저장되고 목록에 반영. (사업자번호를 형식에 안 맞게 넣으면 저장 거부) |
| A8 | 작업 상세 1건 열기 | 연락처·일정 카드 아래에 "수행: 올데이케어 직영" + `화이트코어(으)로 넘기기` 버튼이 보임 (아직 누르지 않음) |

A 가 전부 맞으면 `db/ops/register_whitecore_staff_261006.sql` 을 실행합니다. (5행 등록, 지역수 56 / 35 / 6 / 11 / 11)

## B. 운영자 — 직원 등록 후

| # | 할 일 | 기대 |
|---|---|---|
| B1 | 기사 목록 | 화이트코어 5명이 보임 |
| B2 | 5명 중 1명 편집 화면 | **소속 협력사** 카드에 "화이트코어 / 직원(또는 관리자)" 가 선택돼 있음 |
| B3 | 직영 에어컨 작업 → 배정 추천 / 전체 기사 보기 | **화이트코어 5명이 후보에 없음** |
| B4 | 냉매 접수 자동 배정 | 화이트코어 직원 폰에 수락 요청 알림이 **가지 않음** |
| B5 | 시험 작업 1건 생성(직영, 미배정) → 상세에서 `화이트코어(으)로 넘기기` | "수행: 화이트코어 · 직원 미정" 으로 바뀜. 목록 카드에도 "화이트코어 · 직원 미정" |
| B6 | 같은 작업 → **전체 기사 보기** | 이번에는 화이트코어 직원이 목록에 보임. (추천 목록에는 안 나옵니다 — 에어컨 기능 권한을 비워 두었기 때문. 직원 지정은 협력사 관리자가 하거나 전체 기사 보기에서 합니다) |
| B7 | PC 대시보드 "오늘 원청별" 표 | 시험 작업이 올데이케어 행이 아니라 **화이트코어 (협력사)** 행에 접수 1 로 잡힘 |
| B8 | (C 단계에서 직원이 지정된 뒤) 같은 작업 상세·목록 | "화이트코어 · 한성용" 처럼 표기 |
| B9 | 시험 작업 상세 → `직영으로 회수` | "수행: 올데이케어 직영", 배정 해제, 상태 미배정 |
| B10 | 직영 기사 1명(운영자 겸임 계정 제외) 편집 → 소속을 화이트코어로 저장 → 다시 "올데이케어 직영"으로 저장 | 두 번 다 저장됨. 되돌린 뒤 B3 추천 목록에 그 기사가 다시 보임 |

## C. 협력사 관리자 (한성용 또는 김상욱 계정)

| # | 할 일 | 기대 |
|---|---|---|
| C1 | 전화번호 + 뒤 4자리로 로그인 | 비밀번호 변경 화면 → 변경 후 기사 화면 진입 |
| C2 | 화면 위쪽 토글 | "프로 / 협력사" 토글이 보임 → **협력사** 누름 |
| C3 | 협력사 화면 | 맨 위 "화이트코어", 탭 3개(직원 미정 / 배정됨 / 완료). B5 의 시험 작업이 "직원 미정" 에 1건 |
| C4 | 다른 작업이 보이는지 | 올데이케어 직영 작업, 다른 원청 작업은 **한 건도 보이지 않음** |
| C5 | `직원 정하기` | 화이트코어 5명만 목록에 나옴 (직영 기사 없음) |

| C8 | 토글로 **프로** 전환 | 기사 화면으로 돌아감. 본인에게 배정된 작업만 보임 |

## D. 협력사 기사 (윤인상·제민규·김시민 중 1명)

| # | 할 일 | 기대 |
|---|---|---|
| D1 | 로그인 (뒤 4자리 → 비밀번호 변경) | 기사 화면 진입. 토글 없음 |
| D2 | 작업 목록 | **본인에게 배정된 화이트코어 작업만** 보임. 배정된 것이 없으면 빈 화면 |
| D3 | 새 배정·수락 대기 목록 | 직영 작업의 수락 요청이 **한 건도 없음** |
| D4 | C6 에서 이 직원에게 배정한 뒤 새로고침 | 그 작업 1건이 보임. 상세에서 주소·내비 버튼·사진 업로드 정상 |
| D5 | 아래 **정산** 탭 | 수익·송금 보고 화면 대신 "화이트코어 소속 — 정산은 소속 협력사에서 진행합니다" 안내만 보임 |
| D6 | (시험 작업을 완료 처리했다면) 완료 카드 | "N건 완료" 만 보이고 "오늘 번 돈" 금액은 **없음** |

※ 시험 작업 완료 처리는 권하지 않습니다. 수수료 규칙(묶음 3)이 아직 없어서 주방후드 종목은 저장이 안 되고, 에어컨 종목으로 완료하면 직영 정산식으로 계산됩니다. 완료 흐름 확인은 묶음 3 에서 합니다.

## 끝난 뒤 정리

- 시험 작업은 `직영으로 회수` 후 취소 처리합니다.
- B10 에서 소속을 바꿔 본 직영 기사가 "올데이케어 직영"으로 돌아가 있는지 다시 확인합니다.

## 알아 둘 것 (이번 배포로 바뀌지 않는 것)

- 기사 앱의 작업 **조회**는 이번에 조회 단계에서 나눴습니다: 직영 기사는 "본인 배정 + 직영 열린 작업"만, 협력사 기사는 "본인 배정"만 서버에 요청합니다.
- 다만 앱은 작업이 바뀔 때 서버가 보내는 **실시간 변경 알림**을 받아 목록을 다시 불러오는데, 이 알림 자체에는 바뀐 작업의 내용이 실려 옵니다(직영·협력사 구분 없이, 기존부터 모든 앱이 같음). 화면에는 쓰지 않고 "다시 불러오기" 신호로만 씁니다. 이것까지 막으려면 실시간 알림을 내용 없는 신호로 바꾸는 별도 작업이 필요합니다.
- 화면에 "보안 확인이 필요합니다" 가 나오면 로그아웃 후 다시 로그인하면 됩니다.
