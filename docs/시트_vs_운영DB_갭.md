## 작업번호 prefix 정책

**시뮬** (현재): GAS가 `YYMMDD-K-NNN` 형식으로 무조건 K(쿨가이) 발급. 다른 원청 보내도 K로 나옴 (확인 필요).

**운영** (사장님 알려준 정보):

| 원청 | 종류 | Prefix | 비고 |
|---|---|---|---|
| 유솔 | 외부 | `YS-` | 외부 시트 → 작업DB 자동 동기화 |
| 세스코 | 외부 | `SC-` | 외부 시트 → 작업DB 자동 동기화 |
| 올데이케어 | 직영 | `A-` | PWA 직접 접수 |
| 쿨가이 | 직영 | `A-` | PWA 직접 접수 |
| 용인컴퍼니 | 직영 | `A-` | PWA 직접 접수 |

**여기서 헷갈리는 점**: 시뮬은 `결정사항_추적.md` PRINCIPAL_CODE에서 `쿨가이=K` `용인컴퍼니=Y` `유솔현금=H` `유솔네이버=N` `세스코=C` 매핑이지만, 운영은 직영 3곳 모두 `A-`로 묶음. 시뮬과 운영 정책이 다름.

**해결 방향 (제안)**:
- 시뮬은 시뮬대로 (K/Y/O 등) 두되, 운영 연결 시 어댑터에서 `직영 3곳 → A-` 변환 로직 추가
- 또는 시뮬 GAS도 운영 정책에 맞춰 미리 변경 (직영 = A-, 외부 = 원청별 prefix)

**사장님 답변**: 시뮬을 운영 정책에 맞춰 통일할지 / 시뮬은 그대로 둘지 ___________

## 캘린더 연동 (1+20)

**운영** (사장님 알려준 정보):
- 공용 캘린더 1개 (전체 일정 모음?)
- 기사 캘린더 20개 (기사별 개인)

**시뮬**: 캘린더 연동 없음.

**갭**: 시뮬에서 캘린더 연동 미구현 → PWA의 `scheduledAt`이 시트만 갱신, 캘린더에 안 반영.

**시사점**: 8-A에서 캘린더는 손대지 않음. 별도 슬라이스(예: 8-D 또는 11번대)로 분리.

## 외부 시트 동기화 (운영만)

**운영** 흐름 (추정):
```
외부 유솔 시트 → 트리거 → 운영 작업DB 증분 동기화
외부 세스코 시트 → 트리거 → 운영 작업DB 증분 동기화
PWA → GAS createTask → 운영 작업DB
```

**충돌 가능성**:
- 외부 동기화로 들어온 row와 PWA 생성 row가 같은 작업번호 충돌
- 외부에서 update가 오면 PWA가 만진 필드 덮어씌울 수도

**시사점**: 운영 연결 시 동기화 충돌 방지 정책 필요. 시뮬에서는 이슈 없음 (PWA만 단일 소스).
