## 결정 #4 — `status` 표준 enum 정하기 ⚠️ 중요

**현황**
- PWA INITIAL_TASKS: `약속대기 / 확정 / 진행중 / 완료` 4단계 사용
- PWA UI 코드: `미배정 / 약속대기 / 확정 / 진행중 / 완료` 5단계 처리
- 시뮬 시트 GAS: 신규 row 자동 `미배정`, PWA가 `약속대기` 보내도 무시됨
- 운영 DB: ❓ (사장님이 실제로 어떤 단계 쓰시는지)

**옵션**
| 옵션 | 표준 | PWA 변경 | GAS 변경 |
|---|---|---|---|
| A | `미배정 → 약속대기 → 확정 → 진행중 → 완료` (5단계) | INITIAL_TASKS 12건 일부 보정 | 보낸 status 받아쓰게 픽스 |
| B | `약속대기 → 확정 → 진행중 → 완료` (4단계, "미배정"=신규접수의 약속대기 동일) | 변경 적음 | GAS default를 "약속대기"로 |
| C | 운영 시스템에 맞춤 (ex: 다른 단어 쓰면 그대로) | 운영 enum 따라감 | 동일 |

**추천**: **C** — 운영 표준이 무엇인지 먼저 알려주시고, 시뮬을 그 표준에 맞춰 통일.
- 운영에서 `미배정`을 쓰는지, `대기/배정대기` 같은 다른 단어를 쓰는지가 핵심.
- 시뮬을 임의로 정해놓으면 운영 연결 시 다 바꿔야 함.

**의미적 정리** (사장님 머릿속 그림 확인용):
| 단계 | 의미 | 트리거 |
|---|---|---|
| 미배정 | 신규 접수, 해피콜 통화 전 | 카톡/전화 접수 |
| 약속대기 | 해피콜 통화 후, 일정/기사 미정 | 해피콜 마침 |
| 확정 | 일정 + 기사 둘 다 정해짐 | 해피콜이 배정 |
| 진행중 | 기사가 작업 시작 | 기사 앱 "시작" 버튼 |
| 완료 | 작업 종료 | 기사 앱 "완료" 버튼 |
