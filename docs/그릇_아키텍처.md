# 그릇 아키텍처 — Multi-Tenant + Multi-Category (v4)

**작성일**: 2026-04-30 EOD
**v3 → v4**: 큰 결정 14건 통합 — users 통합 + N role + 다중 폰 master + 인증(전화+PIN) + KA/KB 분리 + 권한/지역/배정 5 테이블 + 가스 자동 배정 Phase 1 진입
**도구**: Supabase (Postgres + Auth + Storage + RLS)

---

## 핵심 원칙

1. **`tenant_id` 모든 데이터 테이블에 박음** — 회사별 격리
2. **`category_id` 작업 관련 테이블에 박음** — 카테고리별 분류
3. **카테고리별 변형은 데이터로** (테이블 분리 X)
4. **공통 그릇은 정형, 카테고리 특화는 JSONB** (`category_data`)
5. **권한은 5 user role + RLS, 한 사용자 N role** — `users` 통합 + `user_roles` M:N
6. **민감 정보 분리** — partner 노출 X 데이터는 `*_internal_*` 컬럼 또는 별도 테이블
7. **정산 = 정책 룩업 자동** (`commission_policies` + `compute_payment`)
8. **인증 = 전화 + 4자리 PIN** (택시앱 스타일, 30일 기억 토큰) ★ Day 1 결정
9. **다중 폰 master 패턴** — 한 사람이 main/gas/work 폰 여러 개 가질 때 `master_user_id`로 통합

## 권한 구조

### 5 role 매트릭스 (DB enum 영문, UI 호칭 한글)

| role (DB) | UI 호칭 | 누구 | 보임 |
|---|---|---|---|
| `owner` | **대표님** | 회사 대표 (이대표 외 공동대표) | 자기 tenant 전체 |
| `operator` | **관리자** | 운영팀 | tenant 전체 R/W |
| `engineer` | **프로님** | 기사 (개인사업자 존중) | 자기 배정만 |
| `partner` | (회사명) | 외부 거래처 (김쿨가이) | 자기 `principal_id` 만 |
| `admin` | 운영팀 | SaaS 자체 | cross-tenant |

DB 컬럼명 / 변수명 / role enum은 **영문 그대로**. UI 텍스트만 한글 변경.

### N 역할 패턴

한 사용자가 여러 role 동시 보유 가능. 예: 조동석 = owner + operator + engineer.
- `user_roles` (M:N) 테이블이 핵심
- `is_primary`로 PWA 기본 진입 화면 결정
- PWA 상단 토글: [대표] [관리자] [프로] (보유한 역할만 표시)

### 다중 폰 master 패턴

한 사용자가 main / gas / work 등 여러 폰 보유. 예: 김태승 = 메인폰(main) + 가스폰(gas).
- 별도 `users` row + `master_user_id`가 main row 가리킴
- `phone_label`로 폰 구분
- 푸시 알림 / 작업 배정은 모든 phone에 발송 (또는 label별 라우팅 — Phase 2)

### partner 보임/안보임 (정확성 ★)

**보임**: 자기 `principal_id` 작업 / `status` / `happycall_status` + `happycall_memo` 외부 / 사진 / 자기 정산분 (`payments_partner_view`) / 분쟁 메모

**안보임**: 다른 principal / `happycall_internal_note` / `work_memo` / `engineer_actual_ad` / `owner_amount` / 다른 거래처 정산

## 핵심 테이블

### 1. 테넌시

```sql
CREATE TABLE tenants (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  slug        text UNIQUE NOT NULL,
  name        text NOT NULL,
  plan        text DEFAULT 'free',
  settings    jsonb DEFAULT '{}'::jsonb,
  created_at  timestamptz DEFAULT now()
);
```

### 2. 사용자 (단일 통합, engineers / app_users 폐기) ★

```sql
CREATE TABLE users (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id       uuid NOT NULL REFERENCES tenants(id),
  code            text,                            -- 'A001','E001','H001' (UI 식별, 비필수)
  name            text NOT NULL,
  phone           text NOT NULL,                   -- ★ 로그인 ID
  email           text,                            -- 선택 (Supabase Auth fake email 가능)
  phone_label     text DEFAULT 'main'              -- 'main' | 'gas' | 'work'
                  CHECK (phone_label IN ('main','gas','work')),
  master_user_id  uuid REFERENCES users(id),       -- NULL = 본인이 master, 보조 폰은 master 가리킴
  region          text,                            -- 거주/주력 지역 (참고용)
  bank_account    text,                            -- 정산 계좌
  must_change_pin boolean DEFAULT true,            -- 첫 로그인 시 PIN 변경 강제
  pin_changed_at  timestamptz,
  last_login_at   timestamptz,
  is_active       boolean DEFAULT true,
  created_at      timestamptz DEFAULT now(),
  UNIQUE (tenant_id, phone)
);

-- 한 사용자 N 역할
CREATE TABLE user_roles (
  user_id      uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role         text NOT NULL CHECK (role IN ('owner','operator','engineer','partner','admin')),
  is_primary   boolean DEFAULT false,              -- PWA 기본 진입 화면
  principal_id uuid REFERENCES principals(id),     -- role='partner' 시 매핑
  granted_at   timestamptz DEFAULT now(),
  PRIMARY KEY (user_id, role)
);

CREATE INDEX user_roles_by_role ON user_roles(role);
```

### 3. 위탁사 (principals)

### 4. 권한 / 지역 / 배정 (Day 1 신규 3 테이블) ★

```sql
-- 프로의 작업 권한 (가스 / 에어컨 청소 / 에어컨 설치 등)
CREATE TABLE engineer_permissions (
  user_id      uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  service_code text NOT NULL,                     -- 'gas_charging' | 'aircon_clean' | 'aircon_install' | ...
  level        text DEFAULT 'main' CHECK (level IN ('main','sub')),  -- ★ v5: 메인 vs 보조 (배정 우선순위)
  active       boolean DEFAULT true,
  granted_at   timestamptz DEFAULT now(),
  granted_by   uuid REFERENCES users(id),
  PRIMARY KEY (user_id, service_code)
);

-- 프로별 작업 시간 (서비스 + 기종 → 예상 분) ★ v5 신규
-- 예: 김기사 + aircon_clean + 벽걸이 = 60분
CREATE TABLE engineer_work_durations (
  user_id         uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  service_code    text NOT NULL,
  appliance_code  text NOT NULL,
  duration_min    int NOT NULL CHECK (duration_min > 0),
  notes           text,
  PRIMARY KEY (user_id, service_code, appliance_code)
);

-- 사용자 선호 (운영 시간 / 야간 / 주말) ★ v5 신규
-- 운영 시간: 기본 08:00 ~ 23:00 + 특수 케이스 (새벽/야간/익일) 토글
CREATE TABLE user_preferences (
  user_id              uuid PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  works_late_night     boolean DEFAULT false,    -- 23시 이후
  works_early_morning  boolean DEFAULT false,    -- 6시 이전
  works_weekend        boolean DEFAULT true,
  works_holiday        boolean DEFAULT false,
  available_from       time DEFAULT '08:00',
  available_to         time DEFAULT '23:00',
  notes                text,
  updated_at           timestamptz DEFAULT now()
);

-- 프로의 담당 지역 (서울 25구 + 경기도)
CREATE TABLE engineer_zones (
  user_id   uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  district  text NOT NULL,                        -- "마포구" | "서대문구" | "고양시" | ...
  active    boolean DEFAULT true,
  PRIMARY KEY (user_id, district)
);

-- 작업 배정 추적 (선착순 또는 수동)
CREATE TABLE task_assignments (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id         uuid NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  user_id         uuid NOT NULL REFERENCES users(id),
  assignment_type text NOT NULL CHECK (assignment_type IN ('manual','auto_first_accept','manual_with_recommendation')),  -- ★ v5: 세척 = 추천+수동
  notified_at     timestamptz DEFAULT now(),
  responded_at    timestamptz,
  status          text NOT NULL DEFAULT '대기'
                  CHECK (status IN ('대기','수락','거절','마감')),
  notes           text
);

CREATE INDEX task_assignments_by_task ON task_assignments(task_id, status);
CREATE INDEX task_assignments_by_user ON task_assignments(user_id, status);
```

**가스 자동 배정 워크플로** (Phase 1):
1. 가스 작업 접수 (`work_type='gas_charging'`, `district='마포구'`, `principal='KA'`)
2. 시스템 룩업 — `engineer_permissions(gas_charging)` ∩ `engineer_zones(마포구)` 인 user
3. 매칭된 user들에게 일괄 푸시 + `task_assignments` row 다수 생성 (`status='대기'`)
4. 첫 수락자 → `responded_at` + `status='수락'` → `tasks.assigned_engineer_id` 세팅
5. 다른 row → `status='마감'` (UI에서 disable)
6. 5분 내 미수락 → owner에게 수동 배정 알림

### 8. 정산 결과 (payments)

```sql
CREATE TABLE payments (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id           uuid NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  computed_at       timestamptz DEFAULT now(),
  computed_by       uuid REFERENCES users(id),

  policy_key        text,
  calc_method       text,

  product_price     int NOT NULL,
  extra_fee         int DEFAULT 0,
  travel_fee        int DEFAULT 0,
  naver_fee         int DEFAULT 0,                 -- 유솔 N 케이스 (Phase 1 수동, Phase 2 자동)

  engineer_amount   int NOT NULL,
  principal_amount  int NOT NULL,
  owner_amount      int NOT NULL,

  is_balanced       boolean GENERATED ALWAYS AS (
    (engineer_amount + principal_amount + owner_amount)
    = (product_price + extra_fee + travel_fee)
  ) STORED,

  -- 정산 흐름 (양방향 확인): 미정산 → 사장님입금 → 기사확인 → 정산완료 (+ 보류/분쟁/지연)
  status                    text DEFAULT '미정산'
    CHECK (status IN ('미정산','사장님입금','기사확인','정산완료','보류','분쟁','지연')),
  paid_at                   timestamptz,    -- ★ v5.1: 사장님 [입금 완료] 클릭 시각
  confirmed_at              timestamptz,    -- ★ v5.1: 기사 [입금 확인] 시각 (원청 정산은 NULL)
  settled_at                timestamptz,    -- 정산완료 시각
  expected_settlement_date  date,
  actual_settlement_date    date,
  notes                     text
);

CREATE INDEX payments_by_task ON payments(task_id, computed_at DESC);
```

## 인증 흐름 (전화 + 4자리 PIN) ★

택시앱 스타일 — 기사/관리자의 IT 친화도 다양 고려.

### 흐름

1. 사용자: 전화번호 (010-xxxx-xxxx) + 4자리 PIN 입력
2. PWA: phone normalize → Supabase Auth signin
3. `must_change_pin=true` → PIN 변경 화면 강제
4. 정상 로그인 → 30일 refresh token ("이 기기 기억")
5. `users.last_login_at` 갱신

### 구현 옵션 (Day 1-2 결정)

- **옵션 A**: Supabase phone signup 직접 (Auth가 phone 지원 시)
- **옵션 B**: `{phone}@allit.local` fake email + PIN as password (호환성 ↑)
  - PIN 4자리는 Supabase 비번 강도 정책 완화 또는 secret salt 추가 필요
  - bcrypt 자동 (Supabase 기본)

### PIN reset 권한

- 사용자 본인: 자신은 못 함 (잊어먹기 쉬워서)
- `owner` / `operator`: 같은 tenant 사용자 PIN reset 가능
  - `users.must_change_pin=true` 설정 + 임시 PIN 발급
  - 사용자 다음 로그인 시 변경 강제

## RLS 정책 (user_roles 기반 재작성)

```sql
ALTER TABLE tasks ENABLE ROW LEVEL SECURITY;
ALTER TABLE payments ENABLE ROW LEVEL SECURITY;
ALTER TABLE photos ENABLE ROW LEVEL SECURITY;
ALTER TABLE task_disputes ENABLE ROW LEVEL SECURITY;
ALTER TABLE task_dispute_messages ENABLE ROW LEVEL SECURITY;
ALTER TABLE task_assignments ENABLE ROW LEVEL SECURITY;

-- 1. 테넌트 격리 (모든 role 공통)
CREATE POLICY tenant_isolation ON tasks FOR ALL
  USING (tenant_id = (SELECT tenant_id FROM users WHERE id = auth.uid()));

-- 2. partner — 자기 principal_id 만
CREATE POLICY partner_select ON tasks FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM user_roles ur
      WHERE ur.user_id = auth.uid()
        AND ur.role = 'partner'
        AND ur.principal_id = tasks.principal_id
    )
  );

CREATE POLICY partner_insert ON tasks FOR INSERT
  WITH CHECK (
    EXISTS (
      SELECT 1 FROM user_roles ur
      WHERE ur.user_id = auth.uid()
        AND ur.role = 'partner'
        AND ur.principal_id = tasks.principal_id
    )
  );

-- 3. engineer — 자기 배정만
CREATE POLICY engineer_select ON tasks FOR SELECT
  USING (
    auth.uid() = tasks.assigned_engineer_id
    AND EXISTS (SELECT 1 FROM user_roles WHERE user_id = auth.uid() AND role = 'engineer')
  );

-- 4. owner / operator — tenant 전체 R/W
CREATE POLICY staff_all ON tasks FOR ALL
  USING (
    EXISTS (
      SELECT 1 FROM user_roles
      WHERE user_id = auth.uid()
        AND role IN ('owner','operator','admin')
    )
  );
```
