## 1. 작업번호 형식 — 원청별 접두어 적용

### 옛 (시뮬 14건 모두 `A-` prefix)
```
A260501-001 (박은서, 올데이케어)
A260501-002 (이수진, 쿨가이)   ← 잘못. 쿨가이 prefix는 A- 같지만 채널 분리 표시 필요
```

### 새 (사장님 spec)
| 원청 | 접두어 | 예시 |
|---|---|---|
| 올데이케어 | `A-` | `A260501-001` |
| 에어컨프로 (쿨가이) | `A-` | `A260501-002` (현재 동일 prefix → 시각적 구분은 색/뱃지로) |
| 용인컴퍼니 | `A-` | `A260513-001` |
| 유솔홈케어 H | `YS-` | `YS260502-001` |
| 유솔홈케어 N | `YS-N-` | `YS-N260504-001` |
| 크리크린 | `CK-` | `CK260506-001` |

**catch 결정 필요**: 올데이케어 / 쿨가이 / 용인이 모두 `A-` prefix. principals.js에 박혀있는 그대로 둘지, 아니면 쿨가이 `K-` / 용인 `Y-`로 분리할지 사장님 결정 필요.

## 2. 정산 흐름 분리 — 원청별 회계 분류

### A. 회사 송금 흐름 (오늘 22:00 마감)
**대상 원청**: 올데이케어 / 에어컨프로 / 용인컴퍼니 / 유솔H / 크리크린
- 기사가 현장에서 받은 현금 (또는 카드 결제분)을 회사로 송금
- 일별 합계 = 그날 완료 작업의 (revenue - 기사 수익)

### B. 유솔N 받을 돈 흐름 (다음 달 15일 입금)
**대상 원청**: 유솔홈케어 N (`usol_n`)
- 네이버 결제 → 정산예정금액 산정 → 다음 달 15일 기사 계좌로 직접 입금
- "회사 송금 X / 받을 돈 ✓" 흐름이라 시뮬 데이터에서 분리 표시

### C. 유솔N 작업의 시뮬 분포
- 5월 작업 = 받을 돈 (6/15 입금 예정) — 누적 표시
- 4월 작업 = 받을 돈 (5/15 입금 예정) — 곧 들어올 돈
- 3월 작업 = 입금 완료 (4/15 입금됨)

## 3. 수수료 정책 v5 적용

### 옛 시뮬 (불일치)
- 모든 작업이 30% 단일 수수료 (FEE_RATE = 0.30 hardcode)
- 원청별 정책 무시

### 새 (`principals.js`의 commissionPolicy 그대로 따름)

| 원청 | 세척 작업 | 냉매 작업 |
|---|---|---|
| 올데이케어 | 직영 (수수료 0) | 기사 50%, 원청 0%, 회사 50% |
| 쿨가이 | (총 - 가짜) × 50% = 원청 / 가짜 = 기사 (비밀) | 원청 10%, 기사 50% |
| 용인 | 원청 10,000 정액 | 원청 10,000 정액 / 기사 50% |
| 유솔H | 원청 15% | 원청 0%, 기사 50% |
| 유솔N | 정산예정 × 15% (정산예정 = 총 / 1.10) | (제외) |
| 크리크린 | 원청 20% | 원청 견적 × 20%, 기사 50% |

→ **단순화**: 시뮬 데이터의 `engineerEarning`을 위 정책에 맞게 박음. 기사 화면에서는 "내 수익"만 표시 (수수료 비율 X).
